
## Non-Azure

Container - a lightweight, isolated package that bundles an application together with its dependencies (libraries, runtime, config) so it runs consistently across environment.
	Shares host operating system's kernel rather than virtualising the whole machine, making it faster to start and lighter on resources.
	Used in:
		- Azure Container Instances (ACI) for single, serverless containers;
		- Azure Container Apps for managed microservices with autoscaling
		- Azure Container Registry (ACR) for storing your container images.

Virtual Machine - a software emulation of a physical computer, with its own guest operating system, running on top of a hypervisor that carves up the underlying physical hardware.
	Heavier than a container but fully isolated, including its own kernel.
	Azure Virtual Machines is one of Azure's core Infrastructure-as-a-Service (IaaS) offerings, letting you provision Windows or Linux VMs on demand. Scale Sets handle groups of identical VMs with autoscaling.

Kubernetes - an Open-Source Orchestration platform (originally from Google) for automating the deployment, scaling, networking and lifecycle management of containers across a cluster of machines.
	It handles scheduling, self-healing, load balancing and rolling updates.
	Azure Kubernetes Service (AKS) - is the managed Kubernetes offering.Azure runs and maintains the control plane for you (free of charge for the control plane itself); you pay for the workers.

Apache Kafka - a distributed event-streaming and message-broker platform for publishing, subscribing to and storing high-throughput streams of events. Widely used for data pipelines, event-driven architectures and real-time analytics.
	Azure Event Hubs provides a Kafka-compatible endpoint, so Kafka clients can talk to it without code changes.
	You can also run Kafka yourself on AKS or VMs, or use `HDInsight`, or third-party managed Kafka from the Azure marketplace

Redis - an in-memory data store, commonly used as a cache, session store, message broker or lightweight database.
	Extremely fast because data lives in RAM; supports structures like strings, hashes, lists and sorted sets.
	Azure Cache for Redis - is a managed offering 

Prometheus - an open-source monitoring and alerting system that scrapes time-series metrics from targets, stores them, and lets you query them with its PromQL language.
	Standard in the cloud-native/Kubernetes world.

Grafana - open-source visualisation and dashboarding tool.
	Plugs into many data sources (Prometheus, Loki, SQL, Cloud monitoring APIs) and renders metrics as dashboards, graphs and alerts.
	Visualises data does no store it.
	Azure Managed Grafana is a managed Grafana instance, tightly integrated with Azure Monitor and the managed Prometheus service, with Entra ID.

Storage Queue - is  a simple message queue service part of an Azure Storage Account.
	Producer drops messages into a queue, consumer pulls them off and processes them.
	Messages are up to 64 KB.
	Queue can hold millions of messages, limited only by the storage account capacity.

Storage Queue Scalers - is an autoscaling mechanism.
	A scaler is a KEDA (Kubernetes Event-Driven Autoscaling) concept, and it also underpins scaling in Azure Container Apps and Azure Functions.
	

## Azure Specific

Event Hub - is a high-throughput event streaming platform.
	Azure's answer to Apache Kafka
	Uses the Kafka protocol.
	Built to ingest millions of events per second:
		Telemetry
		Application logs
		Clickstreams
		IoT sensor data

Event Grid - is an event routing / publish-subscribe service.
	It doesn't store a stream or a backlog of work.
	It distributes discrete event notifications from publishers to subscribers, with filtering, in near real-time.
	Azure services emit events into it natively, and you can publish your own custom events too.

API Gateway - a server that sits in front of backend services and acts as a single entry point for API calls.

Log Analytics - is a feature of Azure monitor: a service that collects, stores and queries log and telemetry data using KQL (Kusto Query Language).
	Underlying store is a Log Analytics workspace.


## General Terminology

Message - is a command or a work item with an expectation attached, the sender expects the receiver to do something with it.

Event - is a lightweight notification that something happened.
	The publisher has no expectation about who handles it or how, it's just announcing a fact.
